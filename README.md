## 软硬件环境剖析

为了彻底讲清为何需要深度适配，这里将目标设备的**硬件底色**与官方软件的**软件鸿沟**清晰拆解：

### 1. 硬件环境（当贝 H1 盒子）
- **芯片 SoC**：海思 HiSilicon **Hi3798MV310**（经典低功耗 IPTV 盒子芯片）
- **CPU 架构**：4 核 ARM Cortex-A7 @ 1.2GHz（32 位 **`armeabi-v7a`**，无 64 位支持）
- **GPU 渲染**：ARM Mali-450
- **运行内存 (RAM)**：**1GB**（开机后系统占用大半，可用运存常年仅剩 200MB~300MB，对内存泄漏和冗余组件极度敏感）
- **机身存储 (ROM)**：8GB eMMC
- **显示输出能力**：硬件与 HDMI 规范最高输出 **1080p 60Hz**，无原生 4K 点对点输出通道
- **多媒体硬解能力**：芯片集成海思专有硬件解码单元（注册为 `OMX.hisi.video.decoder.*`，支持 H.264/AVC、H.265/HEVC、MPEG2、MPEG4、VC1、WMV、AVS 及 Dolby Vision 硬件解码）；但硬解流水线官方上限为 1920×1088，无法承载 4K 原生缓冲区
- **固件特异性**：搭载当贝定制版 Android 4.4.2 固件；系统自带的 `screencap` 截图底层服务损坏（无法直接 adb 截屏，需通过录屏抽取视频帧调试）；系统内置激进的杀后台清理机制（`doRamClear`）。

### 2. 软件环境与平台鸿沟
- **官方软件（网易爆米花 TV v2.6.22）**：
  - **最低系统要求**：官方硬性要求 **Android 5.0 (API 21) 及以上**。
  - **技术栈依赖**：采用高版本 AndroidX / Material Design / Leanback TV 组件库，大量使用 Android 5.0+ 引入的矢量图标（VectorDrawable）、WindowInsets 窗口缩进回调、BottomSheetBehavior 底部弹窗等；
  - **播放内核**：内嵌网易自编译的定制版 libvlc 播放核心，依赖高版本 libc 动态库符号，且其内部的 MediaCodec 硬解策略在 Android 4.4 上由于兼容性问题会静默崩溃或恒定回退至 CPU 软解。
- **目标运行系统（Android 4.4.2 / API 19 KitKat）**：
  - **运行时限制**：运行在老旧的 **Dalvik 虚拟机**上（非 Android 5.0 的 ART 运行时）。Dalvik 在类装载时执行极其严苛的预校验（Pre-verification），遇到 API 21+ 的类引用或方法签名就会抛出不可恢复的 `VerifyError` 导致直接闪退；
  - **C 库缺失**：系统底层 Bionic `libc.so` 极其古老，缺少高版本 C 运行时必备的 28 个基础 POSIX 函数（如 `posix_memalign`、`rand_r` 等）；
  - **渲染机制差异**：Android 4.4 的 `TextureView` 无法良好配合海思的 HWC/OSD 独立硬件图层，容易出现画面大面积黑屏或画面撕裂，必须采用底层的 `SurfaceView`。

## 安装与使用说明（当贝 H1）

1. **下载安装包**：从 [Releases 页面](https://github.com/daloyanf/baomihua-tv-api19-port/releases/tag/v1.5.0) 下载最新的 `baomihua-tv-2.6.22-api19-1.5.0.apk`。
2. **务必先卸载官方版**：由于适配包经过了二次解包与补丁重签名，Android 系统禁止相同包名覆盖安装不同签名的 APK。若此前安装过官方版本，**必须先卸载原版**再安装本包。
3. **安装方式**：将 APK 拷入 U 盘插入当贝 H1 安装，或使用 adb 命令行直装：
   ```bash
   # 若曾安装过官方版，先卸载
   adb uninstall com.netease.filmlytv
   
   # 安装适配版 APK
   adb install baomihua-tv-2.6.22-api19-1.5.0.apk
   ```
4. **启动与使用**：打开应用，使用手机端“网易爆米花”App 扫码登录。在播放界面按遥控器「下键」可唤出清晰度/字幕/音轨菜单。

## 常见疑问解答 (FAQ)

**Q：为什么只在当贝 H1 上适配？其他 4.4 电视盒子能用吗？**  
A：老旧 Android 电视盒子生态极其碎片化。本项目初衷即为个人老设备（当贝 H1）提供可用播放方案，所有的 native 兼容层（海思专有解码器绑定、SurfaceView 刷新通道、底层库符号）都是紧密结合海思 Hi3798MV310 的驱动特性调试的。其他晶晨（Amlogic）或全志（Allwinner）芯片的 4.4 设备缺少海思硬件解码器支持，可能会回退到软解甚至异常，未做支持承诺。

**Q：为什么 4K 视频播出来只有声音、屏幕全黑？**  
A：海思 Hi3798MV310 是一颗百元级 1080p 芯片，其硬件 VPU 解码管道官方上限就是 1080p（1920×1088），Android 4.4 底层图形合成器亦无承载 4K 纹理缓冲区的能力。若挂载的网盘或流媒体源支持服务端转码（如 115、123、Emby 等），可按下键在清晰度中选择 1080p 播放；若为 WebDAV 直连原生 4K 文件，客户端无法强制下变换，只能黑屏。

**Q：这真的是完全由 AI 做的吗？**  
A：是的。整个项目从反编译 APK、分析符号差集、C 语言胶水代码（libcompat）、Smali 补丁注入、VLC 动态库移植，到真机崩溃日志定位，100% 由 **ZCode 搭配 REA 与 LLM 矩阵（GLM / DeepSeek / Gemini）**自动化推导完成。人类仅负责在当贝 H1 电视上插线、按遥控器核验与提供真机现象反馈。
